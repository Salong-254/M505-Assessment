1. Introduction and Problem Definition


A Portuguese bank conducts direct marketing campaigns to promote term-deposit products. Repeatedly contacting customers who are unlikely to subscribe can waste staff time and campaign resources. This project develops a binary classification model to predict whether a customer will subscribe to a term deposit (y) (Babar, 2025).

The business objective is to support more targeted marketing by identifying customers with a higher probability of subscription before additional campaign effort is allocated.

Machine-learning task: binary classification.
Target: y (yes/no).
Inputs: customer characteristics and campaign history available before/around targeting.
Dataset link: https://archive.ics.uci.edu/dataset/222/bank%2B

The duration variable is excluded from the deployment-oriented model because it records the duration of the current contact. A customer-targeting model intended for use before a call should not depend on information that becomes known only during/after that call. This is treated as a potential information-leakage issue (Wang et al., 2026).

The dataset is the UCI Bank Marketing dataset, a public business classification dataset with 45,211 instances and 16 input features. UCI identifies the target as whether the client subscribed to a term deposit.

Project objectives
1. Explore data quality and target imbalance.
2. Build and compare two preprocessing strategies.
3. Train Logistic Regression and Random Forest classifiers.
4. Tune important hyperparameters using cross-validation.
5. Evaluate final models on an unseen test set.
6. identify informative features and translate findings into business recommendations.

EDA interpretation



The dataset has no null values or duplicate rows, so conventional missing-value removal is not required. However, the target is highly imbalanced: approximately 88.3% of observations are no and 11.7% are yes. A model predicting only the majority class could achieve high accuracy while failing to identify likely subscribers. The modelling stage therefore uses F1-score as the main tuning metric and reports precision, recall and ROC-AUC. The numerical variables also have different scales and several contain extreme values, especially balance, duration, pdays and previous. Scaling is therefore expected to be useful for Logistic Regression, while tree-based Random Forest is less sensitive to feature scale (Durib and Gökmen, 2026).
 

4. Data Cleaning and Feature Engineering



duration is removed for the deployment-oriented analysis because it represents the length of the current contact and would not be available before the contact decision. The target is converted to 0/1. Numerical variables use median imputation and categorical variables use most-frequent imputation plus one-hot encoding. Imputation is retained inside the pipeline for reproducibility even though the supplied dataset contains no null values (Dao, 2025).

Two strategies are compared:
- Strategy A: imputation + one-hot encoding.
- Strategy B: imputation + one-hot encoding + StandardScaler.

The comparison is performed on the training data using cross-validation, keeping the test set untouched.
In [4]:
X = df.drop(columns=["y", "duration"])
y = df["y"].map({"no":0, "yes":1})

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=RANDOM_STATE, stratify=y)

num_features = X.select_dtypes(include=np.number).columns.tolist()
cat_features = X.select_dtypes(exclude=np.number).columns.tolist()

def make_preprocessor(scale=False):
    num_steps = [("imputer", SimpleImputer(strategy="median"))]
    if scale:
        num_steps.append(("scaler", StandardScaler()))
    num_pipe = Pipeline(num_steps)
    cat_pipe = Pipeline([
        ("imputer", SimpleImputer(strategy="most_frequent")),
        ("encoder", OneHotEncoder(handle_unknown="ignore"))
    ])
    return ColumnTransformer([
        ("num", num_pipe, num_features),
        ("cat", cat_pipe, cat_features)
    ])

cv5 = StratifiedKFold(n_splits=5, shuffle=True, random_state=RANDOM_STATE)

comparison = []
for name, scale in [("A: no scaling", False), ("B: standard scaling", True)]:
    pipe = Pipeline([
        ("preprocessor", make_preprocessor(scale)),
        ("model", LogisticRegression(C=1, class_weight="balanced",
                                     max_iter=1000, random_state=RANDOM_STATE))
    ])
    scores = cross_val_score(pipe, X_train, y_train, cv=cv5,
                             scoring="f1", n_jobs=-1)
    comparison.append([name, scores.mean(), scores.std()])

comparison_df = pd.DataFrame(comparison, columns=["Strategy","Mean CV F1","Std"])
display(comparison_df)

plt.figure(figsize=(7,4))
plt.bar(comparison_df["Strategy"], comparison_df["Mean CV F1"])
plt.ylabel("Mean cross-validation F1")
plt.title("Preprocessing Strategy Comparison")
plt.xticks(rotation=15)
plt.show()

Preprocessing comparison interpretation



Strategy B should be selected if its cross-validation F1 is higher than Strategy A. Scaling is particularly relevant to Logistic Regression because the optimisation is sensitive to feature magnitude. The test set is not used to choose the preprocessing strategy, which reduces the risk of optimistic evaluation.
 

5. Model Training



Two meaningfully different scikit-learn classifiers are used:

Logistic Regression provides a relatively interpretable linear decision boundary and is a useful baseline for binary classification.

Random Forest is an ensemble of decision trees that can capture nonlinear relationships and interactions. It is less sensitive to feature scaling and can provide feature-importance estimates.

Because the positive class is a minority, class_weight="balanced" is used so that the models give greater importance to the minority class.
In [5]:
# Baseline models using Strategy B
lr_pipe = Pipeline([
    ("preprocessor", make_preprocessor(True)),
    ("model", LogisticRegression(C=1, class_weight="balanced",
                                 max_iter=2000, random_state=RANDOM_STATE))
])

rf_pipe = Pipeline([
    ("preprocessor", make_preprocessor(True)),
    ("model", RandomForestClassifier(n_estimators=200,
                                     class_weight="balanced",
                                     random_state=RANDOM_STATE,
                                     n_jobs=-1))
])

baseline_results = []
for name, pipe in [("Logistic Regression", lr_pipe), ("Random Forest", rf_pipe)]:
    pipe.fit(X_train, y_train)
    pred = pipe.predict(X_test)
    prob = pipe.predict_proba(X_test)[:,1]
    baseline_results.append([
        name, accuracy_score(y_test,pred), precision_score(y_test,pred),
        recall_score(y_test,pred), f1_score(y_test,pred), roc_auc_score(y_test,prob)

6. Hyperparameter Tuning



Hyperparameter tuning is performed for both models using cross-validation. F1-score is used because the positive class is substantially smaller than the negative class and the business objective requires a balance between identifying likely subscribers and limiting false positives.

For Logistic Regression, C controls regularisation strength.

For Random Forest, n_estimators, max_depth, min_samples_leaf and max_features control ensemble size and tree complexity. A smaller leaf size or deeper trees can increase flexibility but may increase overfitting.

The Random Forest search uses RandomizedSearchCV to keep the computational cost manageable while testing multiple parameter combinations.
In [6]:

9. Critical Discussion and Business Recommendations



The final model should be judged against the business objective rather than accuracy alone. The target is imbalanced, so recall and F1 are especially informative. A false negative means that a customer who would subscribe is not prioritised; a false positive means campaign resources may be spent on a customer who does not subscribe (Panagiotou et al., 2024).

Recommendations
- Use the model as a customer-prioritisation tool rather than an automatic decision maker.
- Focus campaign resources on customers with higher predicted subscription probability.
- Review model performance periodically because campaign behaviour and customer characteristics can change.
- Monitor precision and recall, not just accuracy.
- Avoid using duration for pre-contact targeting because it is only known during/after the current call.
- Before deployment, validate the model on more recent operational data and assess the financial value of different targeting thresholds.

Limitations
- The dataset represents a particular banking campaign and may not generalise to another bank or time period.
- The positive class is relatively small.
- Feature importance indicates predictive contribution rather than causation.
- Excluding duration makes the model more suitable for pre-contact targeting but may reduce predictive performance compared with a model that uses information obtained during the call.
- The assignment analysis is offline; real deployment would require monitoring, threshold selection and periodic retraining.
 

10. Conclusion



This project developed an end-to-end supervised machine-learning pipeline for predicting term-deposit subscription. The workflow included exploratory analysis, data-quality assessment, two preprocessing strategies, train/test splitting, two scikit-learn models, cross-validation, hyperparameter tuning and final evaluation on unseen data.

The final model should be selected using the actual test-set results generated above. The strongest model is not necessarily the one with the highest accuracy; the business decision should consider F1, recall, precision and ROC-AUC together. The final recommendation is to use the model as decision support for targeted marketing, subject to validation on current operational data and monitoring after deployment.
